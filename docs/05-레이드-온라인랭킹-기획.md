# 레이드 + 온라인 랭킹/세팅 공유 — 구현 기획서

> 목표: 두 기능을 **완성까지** 끌고 갈 수 있는 단일 문서.
> 전제: 기존 앱은 로컬(Electron + localStorage). **레이드는 로컬 완결**, **랭킹은 온라인(Firebase)** 으로 확정.
> 작성 2026-06-30.

---

## 0. 한눈에

| 기능 | 서버 | 핵심 | 점수/랭킹 |
|---|---|---|---|
| 🐲 레이드 | 불필요(로컬) | 보유 10마리로 강한 보스 처치 | 등급별 **클리어 타임** |
| 🏆 랭킹/세팅공유 | **필요(Firebase)** | 스테이지·레이드 순위 + 남의 세팅 열람 | 진행도·레이드타임 |

**연결**: 레이드 클리어 타임 → 랭킹 점수, 레이드 팀 → 공유 세팅. 그래서 **레이드 먼저(로컬) → 그 위에 랭킹** 순서.

**기존 데이터 모델(참고)**
- 멤버 `m = { en, lv, xp, learned[], active[4], equip:{ main, boost, tech } }`, 각 장비 `{ uid, key, star }`.
- `state`: `party[≤3]`, `bench[≤150]`, `inv[≤500]`, `prog:{region,route,wave,maxRegion,badges,...}`, `settings`, `released`.
- 저장: localStorage `pkmnRoom`(v7), `loadState`가 누락필드 backfill.

## 1. 🐲 레이드

### 1.1 컨셉 / 루프
평소 3마리 파티와 **별개**로 보유 포켓몬 중 **최대 10마리**를 레이드 팀으로 편성 → 등급별 **레이드 보스**(매우 강함)에 도전 → **제한시간 내 처치**가 목표, 클리어 타임이 점수. 무제한 재도전으로 베스트 타임 갱신.

### 1.2 보스 / 등급 / 스케일
- **등급 tier = 1,2,3,…** (무한 확장). 높을수록 보스 강함·보상↑.
- 보스 종족: `CHAMP_POOL`(bst≥580, 전설 포함)에서 선택, 등급별 고정 또는 회전.
- 보스 스탯(기존 `statAt`·`regionMult` 재사용):
  ```
  bossLv   = clamp(50 + tier*15, 1, 999)
  hpMult   = 30 * Math.pow(1.5, tier)        // 매우 두꺼운 단일 HP (10마리가 협공 전제)
  atkMult  = Math.pow(1.5, tier*0.5) * 0.6   // 즉사 방지(여러 마리가 버티게)
  bossHP   = statAt(bst기반 hp, bossLv, true) * hpMult
  ```
  → 수치는 시뮬로 튜닝(목표: 적정 세팅이 제한시간의 50~80%에 클리어).
- **제한시간**: 기본 90초(배속 무관 실시간). 초과 시 실패(보스 잔여 HP% 표시).

### 1.3 전투 (엔진 재사용)
- 기존 `heroAttack/enemyAttack/calcDamage/applyStatus` 그대로 사용.
- **모드 분기**: `raidActive` 플래그. tick에서 raidActive면 `raidHeroes`(≤10) vs `raidBoss` 루프 구동(기존 party vs wave 대신).
- **보스 행동**: 기본=선두 타격. (확장: 일정 주기 **광역(AoE)** 으로 전체 타격 → 생존/힐 세팅 의미 부여.)
- **레이아웃**: 10마리는 좌측에 **작은 스프라이트 2열**(또는 세로 스택), 보스는 우측 크게. 각자 HP바·기술 이펙트.
- 기절한 멤버는 빠지고 남은 멤버로 계속(전멸=실패).

### 1.4 점수 / 랭킹 연동
- 클리어 시 `timeMs` 기록. 등급별 **best time** 저장(`state.raid.best[tier]`).
- 랭킹 점수 = (등급, 클리어타임). 보드는 **등급별 타임 오름차순**(빠를수록 1등). 진행 지표 = 최고 클리어 등급.

### 1.5 보상
- **첫 클리어(등급별)**: 큰 골드 + **보장 고등급 장비**(높은 ★/레어) + (옵션)레이드 전용 재화.
- **반복 클리어**: 작은 골드 + 일반 장비(메인 경제 안 깨지게 소폭).
- 베스트 타임 갱신 시 추가 소량 보상(선택).

### 1.6 데이터 모델
```js
state.raid = {
  team: [/* 멤버 참조 ≤10 (party/bench의 동일 객체 참조) */],
  maxTier: 0,                 // 최고 클리어 등급
  best: { /* tier: timeMs */ },
  cleared: { /* tier: true */ },
}
```
- 팀은 멤버 **참조** 저장(진화/방생 시 동기화 필요 → 저장 시 살아있는 멤버만 필터, 방생/벤치이동과 무관하게 보유중이면 유지).
- localStorage 저장/`loadState` backfill에 `raid` 추가(기존 세이브 호환).

### 1.7 UI
- 상단바에 **🐲 레이드 탭** 추가(기존 탭 시스템 `openPanel('raid')`/`renderRaid()` 분기).
- 레이드 패널:
  - **팀 편성**: 보유 목록(party+bench) 그리드, 탭으로 10칸 채우기/빼기. "✨ 추천 편성"(전투력 상위 10 자동).
  - **등급 선택**: 1 ~ (maxTier+1). 잠긴 등급은 회색.
  - **레이드 시작** → 전용 전투 화면(아레나를 raid 모드로 전환 또는 오버레이) + 타이머 + 보스 HP.
  - **결과**: 클리어/실패, 타임, 보상, "🏆 랭킹 등록"(기능 2).

### 1.8 신규 함수/변경점(코드 지도)
- `room.js`: `let raidActive=false, raidHeroes=[], raidBoss=null, raidTimer`. `spawnRaidBoss(tier)`, `startRaid(tier)`, `endRaid(win)`, `renderRaid()`, `raidTick`(또는 tick 내 분기), `renderRaidArena()`.
- `room.html`: 🐲 탭 버튼, 레이드 오버레이/영역.
- `room.css`: 레이드 레이아웃(10마리 mini, 보스 big, 타이머/HP).

### 1.9 단계(Phase) + 완료기준
- **R1 팀 편성·저장**: 보유에서 10마리 선택·저장·복원. (✅ 완료: 팀 유지/방생 동기화 + 멤버 `mid` 안정식별자)
- **R1.5 팀 도구·기술 세팅**: 레이드 팀 각 포켓몬 도구 장착/해제·자동, 기술 자동 + 팀 전체 자동. (✅ 완료: 가방이 파티전용이라 임의멤버용 `equipMemberGear`/`unequipMember` 추가)
- **R2 전투**: 10 vs 보스, 제한시간(90s), 클리어/실패. (✅ 완료: 엔진 재사용, `raidActive` 분기 + `enemyDefeated`/`partyWipe` 가드, 좌측 2열 미니배치 + 보스, 타이머바)
- **R3 등급·스케일·보상**: (✅ 완료) 등급별 보스 **고정**(종족·HP·공격력 결정적 → 랭킹 공정). HP=`60000·1.8^(t-1)`, 공격=`30·1.3^(t-1)`, Lv=`45+12t`. 보상=골드(첫클리어 2배)+고성 장비 드롭(첫클리어 3개/반복 2개). 클리어 시 다음 등급 해금, 베스트 클리어타임 기록.
- **R4 폴리시**: (✅ 완료) 타이머바·생존수·베스트타임·등급선택기·추천편성(상위10) + **보스 광역기**(25%, 전원 0.4배 타격→힐/내구 보상) + **격노**(보스 <30% HP 시 공속 1.66배) + **팀 프리셋 3슬롯**(저장/불러오기) + **♻ 자동 재도전**(승리 시 같은 등급 반복=메달 파밍, 실패 시 중단).
- **QoL 추가**: 벤치 **전투력순 정렬**, 파티 헤더 **⚔ 총 전투력** 표시. 클리어 타임 표기 소수 2자리(빠른 클리어 구분). 레벨캡 제거(999 상한).

#### 1.9.1 도구 공유 설계 결정 (스테이지↔레이드 충돌 해결)
- **문제**: 도구는 1개뿐(공유 인벤)+포켓몬당 1세트인데 스테이지(3)·레이드(10)가 같은 포켓몬 공유 → 레이드 세팅 시 스테이지 세팅이 깨짐(특히 "전체 자동"이 기존 장비 재배치).
- **결정(A안)**: **포켓몬당 1세트 통합** — 포켓몬이 도구를 항상 지님, 스테이지·레이드 동일 사용. + **자동장착 비파괴화**: `autoEquip(member, fillOnly)` — `fillOnly`면 이미 낀 슬롯은 건드리지 않음. 팀 전체 자동/기술 자동도 "빈 칸만" → 손으로 맞춘 세팅 보존. (B 별도 로드아웃=도구 2배·복잡, C 무소모복사=희소성 붕괴 → 모두 비채택.)

#### 1.9.2 밸런스 실측 (lv66~80·무장비 10마리 기준)
- 지속 DPS ≈ **5,000/s**(버프 셋업 후 정상상태). 등급1(HP 6만)=클리어 ~14s·8/10 생존. 등급2(HP 10.8만)=보스 12%까지 깎고 전멸 → **장비 필요(의도된 벽)**. 등급당 HP×1.8로 ~10등급(12M)에서 자연 상한.

## 2. 🏆 온라인 랭킹 + 세팅 공유

### 2.1 백엔드: Firebase Firestore (무료 티어)
- 이유: 서버리스·무료(Spark: 1GB, 읽기 5만/쓰기 2만 per day)·익명 인증·REST. 운영 부담 최소.
- **당신(lie-0022)이 할 일(1회)**:
  1. console.firebase.google.com → 프로젝트 생성(예: `pokemon-raid`).
  2. Firestore Database 생성(프로덕션 모드).
  3. Authentication → **익명 로그인** 활성화.
  4. 프로젝트 설정 → 웹앱 등록 → `apiKey`/`projectId` 확보(공개되어도 안전, 보안은 규칙으로).
  5. 보안 규칙 배포(아래 2.3).
- 앱에는 `apiKey`/`projectId`만 박음.

### 2.2 클라 연동 방식
- **REST + fetch** (SDK 미번들 → CSP 단순). 
  - 익명 토큰: `POST identitytoolkit.googleapis.com/v1/accounts:signUp?key=APIKEY` → `idToken`,`localId(uid)` 획득(앱 최초 1회, 토큰 캐시/갱신).
  - 쓰기/읽기: `firestore.googleapis.com/v1/projects/PID/databases/(default)/documents/...` (Authorization: Bearer idToken).
- **CSP 변경**(room.html): `connect-src 'self' https://firestore.googleapis.com https://identitytoolkit.googleapis.com securetoken.googleapis.com;`
- **오프라인/실패**: 모든 랭킹 호출은 try/catch, 실패 시 "오프라인" 표시. **코어 플레이 절대 안 막음**.

### 2.3 보안 규칙(스케치)
```
match /raidScores/{id} {
  allow read: if true;                       // 랭킹 공개
  allow create, update: if request.auth != null
    && request.resource.data.uid == request.auth.uid
    && request.resource.data.timeMs is int && request.resource.data.timeMs > 0   // ※ 빠른 클리어(<3s)도 정상이라 하한은 0 초과만
    && request.resource.data.tier is int
    && request.resource.data.setup.size() < 4000;   // 페이로드 상한
}
match /stageScores/{uid} {
  allow read: if true;
  allow write: if request.auth != null && uid == request.auth.uid;
}
```
- 부정점수: 클라 제출이라 위조 가능 → **캐주얼이라 가벼운 검증만**(시간 하한·필드 검증). 완전 방지는 비현실적(서버 시뮬 필요)이라 감수.

### 2.4 데이터 모델(Firestore)
- `raidScores/{uid_tier}`: `{ uid, name, tier, timeMs, setup, ts }` — uid+tier당 1개(베스트 upsert). 보드 = `where tier==T order timeMs asc limit 50`.
- `stageScores/{uid}`: `{ uid, name, region, badges, ts }` — 진행도 보드(`order region desc, badges desc`).

### 2.5 세팅 인코딩(공유 포맷)
```js
setup = { v:1, by:name, team:[ { en, lv, active:[k,k,k,k], equip:{ main:{key,star}|null, boost:..., tech:... } }, ... ] }
encoded = base64( JSON.stringify(setup) )   // ~1~2KB
```
- 열람: 디코드 → 멤버 상세처럼 읽기전용 렌더(포켓몬·기술4·도구★ 표시). 도구/기술 정의는 로컬 데이터(`ITEM_DEFS/MOVES/BY_EN`)로 해석.
- 호환: `v` 버전 필드로 향후 포맷 변경 대비. 모르는 key/en은 스킵.

### 2.6 닉네임 / 식별
- 닉네임 `state.settings.nick`(최초 등록 시 입력, 욕설필터·길이제한). 식별 uid=익명 Firebase uid(설치당 고정). 계정 없음.

### 2.7 UI
- 상단바에 **🏆 랭킹 탭**(또는 레이드 결과/로드맵에서 진입).
- 랭킹 패널 탭 2개:
  - **레이드 랭킹**: 등급 선택 → 상위 50(순위·닉네임·타임). 항목 탭 → **세팅 열람**(그 사람의 10마리·기술·도구).
  - **스테이지 랭킹**: 진행도(최고 지방·배지) 상위. 항목 탭 → 파티 세팅 열람.
- **등록**: 레이드 클리어 시/수동 "🏆 등록"으로 {닉, 등급, 타임, 세팅코드} 업로드(베스트만). 스테이지는 진행 시 자동 best 업로드(쓰기 절약 위해 갱신 시에만).

### 2.8 단지(Phase) + 완료기준
- **L1 백엔드 셋업**: (✅ 완료 — **기존 `ssazim`(겁나쎄짐) 프로젝트 RTDB 재사용**) Firestore+익명auth 방식을 폐기하고 **Realtime Database REST**로 전환(인증 불필요, URL만). `room.js` `const FIREBASE = { rtdb: 'https://ssazim-default-rtdb.firebaseio.com' }`. CSP도 해당 도메인으로 갱신. 포켓몬은 `pkmnRaid`/`pkmnStage` 노드만 사용(게임 `leaderboard`와 분리). 식별자는 `state.rankUid`(설치당 로컬 생성). **읽기 라이브 검증 완료**(앱에서 실제 DB 조회 성공). 쓰기는 RTDB 규칙이 루트 개방이어야 함(게임이 `leaderboard`에 쓰는 걸로 보아 개방 추정 — 첫 등록으로 최종 확인).
- **L2 등록/조회**: (✅ 클라 완료) 익명 토큰(signUp+refresh, uid 설치당 고정)→`raidScores/{uid}_{tier}` upsert(신기록만) / runQuery(tier==T, **클라 정렬**로 복합색인 불필요)→상위 50. 레이드 승리 시 자동 등록.
- **L3 세팅 열람**: (✅ 완료) base64 인코딩/디코딩(v1) + 읽기전용 세팅 렌더(포켓몬·기술4·도구★). 랭킹 항목 "세팅" 버튼 → 열람.
- **L4 스테이지 보드**: (✅ 완료) `stageScores/{uid}` upsert(챔피언 격파 시)→지방·배지 정렬. + 닉네임(state.settings.nick)·오프라인 try/catch(실패 시 "오프라인" 표기, 코어 무영향).
- **남은 것(L1만)**: 아래 절차로 Firebase 프로젝트 만들고 apiKey/projectId를 `FIREBASE`에 채우면 전 기능 활성.

#### 2.8.1 Firebase 켜는 법 (사용자 1회, ~5분)
1. console.firebase.google.com → **프로젝트 추가**(예: `pokemon-raid`).
2. **Firestore Database** 만들기(프로덕션 모드, 지역 아무거나).
3. **Authentication → 시작하기 → 로그인 방법 → 익명 사용 설정**.
4. **프로젝트 설정(⚙) → 내 앱 → 웹앱(</>) 추가** → 표시되는 `apiKey`, `projectId` 복사.
5. `room.js`의 `const FIREBASE = { apiKey: '여기', projectId: '여기' };` 채우기(공개키라 노출 안전).
6. Firestore **규칙** 탭에 §2.3 규칙 붙여넣고 게시.
7. 앱 재시작 → 🏆 탭에서 닉네임 저장 → 레이드 클리어하면 자동 등록·조회.

---

## 3. 두 기능 연결
레이드 `endRaid(win)` → 클리어 시 `submitRaidScore(tier, timeMs, encodeSetup(raid.team))`. 랭킹에서 남의 레이드 세팅을 보고 "내 레이드에 시험 적용"(읽기전용 미리보기 → 원하면 내 팀에 복사, 단 보유 포켓몬/도구 없으면 회색).

## 4. 로드맵(권장 순서)
1. **레이드 R1~R3**(로컬 완결, 즉시 재미) →
2. **랭킹 L1~L2**(백엔드+레이드 타임 등록/조회) →
3. **세팅 열람 L3** →
4. **스테이지 보드 L4** + 레이드 R4 폴리시.

각 Phase는 미리보기 검증 + 데이터 호환(기존 세이브) 유지. 빌드는 묶음 단위로.

## 5. 아직 정할 것
- 레이드: 보스 **AoE 유무**, 제한시간 길이, 보상 종류(전용 재화 둘지), 팀 "최대 10" vs "정확히 10".
- 랭킹: 닉네임 정책(중복 허용?), 보드 노출 수(상위 50/100), 부정점수 어디까지 감수.
- Firebase 프로젝트는 **당신 계정**으로 생성(무료). 원하면 셋업 절차를 단계별로 같이 진행.

## 5.5 v1.2.0 배포 전 대규모 개편 (실사용자 배포 기준 점검 반영)
- **개체치(IV)**: 멤버 `iv` 0~31(본가 공식 `(2·종족값+iv)·lv/100`). 신규 랜덤·기존 백필. 🦸 상세에 표시(+색), 🍬개체치사탕(레이드 상점 🏅8)으로 +1.
- **이로치 개편**: 직접 메달 구매 → **✨이로치사탕**(상점 🏅100) 소비로 변경. 🐉전설은 🏅250(사탕보다 빡세게).
- **레벨캡 확정**: 상한 = 스테이지 적Lv+40, **999 절대상한 폐지**(지방↑=캡↑ 무한). v9 마이그레이션에서 기존 오버레벨을 캡으로 축소(xp 0). 적/보스 레벨도 999 클램프 제거.
- **레이드 난이도 개편(실측 튜닝)**:

## 6. 리스크 / 메모
