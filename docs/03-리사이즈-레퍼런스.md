# 배틀룸 크기 조절 — 레퍼런스 & 적용 설계

## 문제
기존: 투명·프레임리스 창 + `resizable:true`(OS 가장자리 리사이즈). 결과가 **부자연스러움**.

## 레퍼런스에서 확인한 사실
1. **투명 창은 OS 리사이즈가 불안정** — Electron 공식/이슈: "Transparent windows are not resizable; setting `resizable:true` may make a transparent window stop working on some platforms." ([electron#49173](https://github.com/electron/electron/issues/49173), [BrowserWindow 문서](https://www.electronjs.org/docs/latest/api/browser-window))
2. **`setAspectRatio`는 리사이즈 버그** — 테두리 드래그로 **작게는 되지만 크게는 안 됨**, `setSize` 등 프로그램 호출엔 비율 미적용. ([electron#5395](https://github.com/electron/electron/issues/5395))
3. **프레임리스 드래그 영역이 리사이즈 핸들을 가림** — `-webkit-app-region: drag`가 가장자리 리사이즈를 막음. ([electron#3022](https://github.com/electron/electron/issues/3022), [Custom Window Styles](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles))
4. **콘텐츠 스케일링**: 캔버스/게임은 **고정 디자인 해상도 + `transform: scale()`로 뷰포트에 맞춰 줌**하는 것이 표준(레터박스/비율 유지). ([Code Theory: Scaling Canvas](https://codetheory.in/scaling-your-html5-canvas-to-fit-different-viewports-or-resolutions/), [zachstronaut gist](https://gist.github.com/zachstronaut/1184900), [Konva Responsive](https://konvajs.org/docs/sandbox/Responsive_Canvas.html))

## 채택한 설계 (정석)
1. **OS 리사이즈 끔** (`resizable:false`) — 투명 창 버그 회피.
2. **커스텀 리사이즈 그립**(우하단, 보이는 손잡이): `pointerdown`→`setPointerCapture`→`pointermove` 델타를 IPC로 메인에 전달 → 메인이 `setBounds`.
3. **비율 고정**(820:210): 메인이 width만 받고 height = width/ASPECT 로 계산 → 이상한 비례 불가.
4. **하단 중앙 도킹 유지**: 리사이즈 시 가로 중앙·화면 하단에 다시 정렬.
5. **콘텐츠 scale-to-fit**: `#room`을 **고정 디자인 크기(820×210)**로 두고 `transform: scale(min(W/820, H/210))` → **창 크기에 따라 전체가 통째로 줌**(글자·스프라이트·버튼 모두 자연스럽게).
6. **프리셋 유지**(트레이 작게/보통/크게) — 비율 동일한 너비(600/820/1080)로 매핑.

→ 결과: 그립을 끌면 부드럽게 비율 유지 줌, 트레이로 한 번에 프리셋. OS 투명창 버그 없음.
